# Oracle Registry — The Moat Layer

The strategic asset is not "number of APIs".

It is:

```text
number of high-quality Oracle domains
× historical depth
× semantic interoperability
× verified cross-oracle joins
× outcome feedback
```

## OracleManifest

Every oracle declares:
- domain
- entity types
- metrics
- dimensions
- geography
- cadence
- evidence semantics
- source families
- interface
- cost/rate constraints
- legal/license notes
- confidence model

## Oracle classes

### AI Market Oracle
OpenRouter + HF + OSS + MCP + attention.

### Global Reality Oracle
Unignorant and country/global stats.

### Research Oracle
OpenAlex + recent paper feeds.

### Labour Oracle
global/national labour, wages, occupations, vacancies.

### Policy Oracle
official policy, grants, regulations, subsidies.

### Trade/Supply Oracle
Comtrade/Eurostat/Unignorant trade + supply chains.

### Portfolio Outcome Oracle
your own product behavior.

## Oracle combination graph

The MetaFactory can ask:

```text
Which oracle pairs have compatible dimensions
but have never been joined?
```

Then prioritize joins with:
- semantic relation templates;
- high-value market topics;
- good evidence;
- low existing solution coverage.

## Compounding moat

After product outcomes arrive, store:

```text
oracle combination
→ opportunity
→ solution
→ factory
→ product
→ real outcome
```

Later the system can learn:

> Labor + training-policy joins historically produced useful opportunities;
> generic attention-only joins did not.

That is much more defensible than another trend scraper.
