# VentureLab Factory Line

*Driven by hermes kanban, not Python scripts*

---

## How It Works

```
IDEA → SPECIFY → DECOMPOSE → BUILD → VERIFY → DONE
```

### Step 1: Create Board

```bash
hermes kanban boards create venturelab
hermes kanban boards switch venturelab
```

### Step 2: Create Task

```bash
hermes kanban create "Build Knee MVP" --body "Build cost-quality cliff API from specs/knee/architecture.md"
```

### Step 3: Specify Task (hermes fleshes out details)

```bash
hermes kanban specify <task_id>
```

### Step 4: Decompose (hermes breaks into subtasks)

```bash
hermes kanban decompose <task_id>
```

### Step 5: Dispatch Workers

```bash
hermes kanban dispatch --max 5
```

### Step 6: Workers Claim and Build

Workers automatically:
1. Claim ready tasks
2. Read specs
3. Build code
4. Mark complete

### Step 7: Verify

```bash
hermes kanban request-review <task_id>
```

---

## Current Board Status

```bash
hermes kanban list
```

Shows all tasks with status:
- ready: can be worked on
- running: worker is building
- review: needs verification
- done: completed

---

## Key Commands

| Command | What It Does |
|---------|--------------|
| `hermes kanban create` | Create new task |
| `hermes kanban specify` | Flesh out task details |
| `hermes kanban decompose` | Break into subtasks |
| `hermes kanban dispatch` | Spawn workers |
| `hermes kanban claim` | Worker claims task |
| `hermes kanban complete` | Mark done |
| `hermes kanban review` | Request verification |
| `hermes kanban list` | See all tasks |

## What Gets Built

For each product:

1. **Report** — from reports/{product}/report.md
2. **Architecture Spec** — from specs/{product}/architecture.md
3. **MVP Code** — built by workers
4. **Tests** — written by workers
5. **Documentation** — generated by workers

---

## Anti-Cheat

**"Nothing written in markdown counts as evidence."**

Workers must:
- Write actual code
- Run actual tests
- Log actual results
- Commit actual changes
